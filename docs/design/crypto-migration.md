# 币圈版交易 agent 迁移方案

> 从旧 Claude 账号的文档导出（2026-11-19）。这是 2026-11-05 的方案草稿，最终实现以 CLAUDE.md 和 README.md 的“币圈部分”为准（例如交易所最后定的是 OKX，不是文中推荐的 Kraken）。

2026-11-05 · 草案，待 Minglu 确认后再写代码

## 1. 先回答：现在的系统里有 agent 吗？

有，但是被刻意“关在笼子里”。现有 ibkr-agent 是**规则驱动 + Claude 当研究员**：

- 代码算基线（FCF 收益率 + 增长 − 杠杆惩罚），见 `valuation.py`。
- Claude（`research.py`）只读数据，写多空论点，给出 ±3pp 以内的调整和信心等级。调用失败就当没意见。
- 买不买、买多少、怎么下单，全部由确定性代码（`decision.py`、`risk.py`）决定。

这样做的原因：模型会有偶发的错误和过度自信，钱少的时候一次错单的手续费和亏损就很伤。迁移到币圈时**保持这个结构不变**，只换数据源、交易所和成本参数。

## 2. 可以直接复用的部分（约 60% 代码）

| 模块 | 处理方式 |
| --- | --- |
| `decision.py` 买入线/卖出线/摊薄成本/滞后带 | 原样复用，只改参数 |
| `risk.py` kill switch、回撤熔断、单只上限、报价异常、限价不穿价 | 原样复用；“行业上限”改成“板块上限”（L1、DeFi 等） |
| `journal.py`、`reconcile.py`、`report.py`（graduate 门槛） | 原样复用，基准从 SPY 改成 BTC |
| `research.py` 的结构（结构化输出、上限、失败即不调整） | 复用，只换系统提示词和输入数据 |
| `costs.py` | 改成百分比费率（maker/taker）+ 点差 + 滑点 |
| 配置、dry\_run、kill switch、周任务脚本 | 复用 |

## 3. 需要新写或替换的部分

### 3.1 交易所接入：`broker.py` → `ccxt` 适配层

- 抽一个 `Broker` 接口（取账户、取报价、下限价单、查成交、撤单），IBKR 和交易所各实现一份。
- 交易所推荐 **Kraken**（已有 MiCA 牌照，EUR 入金便宜，ccxt 支持成熟）。备选 Bitstamp、Coinbase。
- 另一条路：IBKR 自己也提供加密货币交易，如果你的账户能开通，整个 broker 层可以直接复用，不需要新交易所。需要你在 Client Portal 里看一下“交易权限 → 加密货币”是否可选。
- 下单一律用 **post-only 限价单**（只做 maker，费率更低），等不到成交就撤单，和现在的 300 秒逻辑一样。
- 币圈 24/7，去掉美东交易时段限制，改成“避开周末低流动性”的固定时间运行。

### 3.2 模拟盘

Kraken 现货没有官方测试网。做法：写一个**本地模拟 broker**，用真实盘口价格 + 模型手续费模拟成交，日志照写。这样 12 周考核门槛（graduate）可以原样用在币圈。

### 3.3 基线：币圈没有财报，用什么代替？

这是最大的区别，也要诚实说清楚：大多数币没有现金流，“合理估值”远比股票弱。建议分两层：

1. **核心仓（BTC、ETH）**：不估“预期收益”，改用**目标配置 + 再平衡带**。例如 BTC 60% / ETH 40%，偏离超过 10 个百分点才调。基准就是 BTC。
2. **卫星仓（可选，最多 2 个，总占比 ≤20%）**：只考虑有真实协议收入的币，基线公式类比股票：
   - 实际收益率 = 协议收入（给持币人的部分）/ 完全稀释市值（数据来源 DefiLlama，免费 API）
   - 减去 代币增发率（稀释）
   - 减去 未来 12 个月解锁占比的惩罚
   - 再扣掉流动性惩罚（日成交额太低的不买）

Claude 依然只做 ±3pp 的调整，输入是上面这些数字 + 代币经济、监管和安全事件。

### 3.4 成本参数（比美股贵很多）

- 现货费率大约 0.2%–0.4%（maker）到 0.4%–0.6%（taker），以交易所官网为准。IBKR 美股一笔 $1 左右，按 €2000 规模算，币圈来回一次的成本是美股的数倍。
- 结论：**换手要更低**。建议最小单笔 €100，再平衡带放宽，持有期按 2 年摊薄。
- EUR 入金 SEPA 通常免费，出金有小额固定费，记入成本。

## 4. 风控和安全的新增规则

- 交易所 API key 只开“查询 + 交易”，**不开提币权限**，并绑定 IP 白名单。
- 只做现货，不用合约、不用杠杆、不借贷、不质押（质押涉及锁仓和税务，第一版不做）。
- 稳定币只当现金用，只持 MiCA 合规的 EUR/USD 稳定币（如 USDC、EURC），或者直接留 EUR。
- 回撤熔断阈值从 20% 放宽到 35%（币圈 30% 回撤很常见，20% 会频繁误触发），这是你需要拍板的参数。
- 单币上限：BTC/ETH 各 ≤70%，卫星每个 ≤10%。

## 5. Claude API 成本估算（预算 $100）

现有配置是 Opus 5.5、effort high。价格：输入 $4 / 百万 token，输出 $20 / 百万 token；Batch API 半价。

每次评估一个标的：输入约 1.5k token，输出（含思考）估计 3k–6k token，约 **$0.07–0.13/次**。这是估算，跑一次后看 `usage` 字段就知道真实数字。

| 场景 | 每周调用 | 每年成本（Opus 5.5 high） | 用 Batch 半价 |
| --- | --- | --- | --- |
| 只跑美股（8 只） | 8 | 约 $30–55 | 约 $15–28 |
| 美股 + 币圈（8 + 4） | 12 | 约 $45–80 | 约 $22–40 |

省钱手段（按推荐顺序）：

1. 周任务不需要即时结果，改用 **Batch API**，直接省一半。
2. 只在数据变化时才重新问 Claude（新财报、价格变动 >10%、协议数据变化），否则沿用上次结论。大概能再省一半。
3. BTC/ETH 核心仓按配置再平衡，不需要 Claude 打分。

做完 1 和 2，$100 足够美股 + 币圈一起跑 2 年以上。代码里加一个**月度花费上限**（例如 $8），超了就自动跳过研究，等同 `--skip-research`。

## 6. 德国/欧盟监管和税务要点（不是税务建议，请以税务顾问为准）

- **MiCA**：2024 年底全面生效，在德国只用有 MiCA 授权（CASP）的交易所。Kraken、Bitstamp、Coinbase 均已获批，以 BaFin/ESMA 名单为准。
- **持有满 1 年免税**（§23 EStG 私人出售交易）：加密货币持有超过 1 年卖出，收益免税。不满 1 年，全年私人出售收益合计低于 €1,000 免税，超过则全额按个人所得税率交。
- 这一点和美股不同：美股在德国不论持有多久都交 25% 资本利得税（加团结税）。所以**币圈的卖出规则要加入“持有期感知”**：同一个币按 FIFO 记录每一批买入日期，未满 1 年的批次，只有预期损失明显大于税负时才卖。这是要新增的代码逻辑。
- 质押、借贷收益按其他收入计税（年度 €256 免征额），第一版不做，避免复杂化。
- **DAC8**：从 2026 年起交易所会向税务局报送交易数据，journal 要能导出年度交易明细（买入日、卖出日、成本、收益）。

## 8. 快思考 + 慢思考：开源项目怎么借鉴

结论：借它的**分层结构**（慢模型定边界，快层在边界里执行），不借它的**交易频率**（秒级合约交易）。按 €2000 本金和 $100 预算，秒级交易会被手续费吃掉。

### 8.1 找到的相关项目（2026-11-05 在 GitHub 上搜的）

“jev”是 TypeSafe AI 的 **Jev**，一个专门做快速结构化判断的 “System One” 模型（几十毫秒返回选项 + 概率）。“grokbot”是 Grok Bot 这个 agent 宿主。和你描述最像的几个：

### 8.2 用到我们系统里的样子

1. **慢思考（Opus 5.5，每周一次）**：对每个标的输出“本周边界”，比现在的 ±3pp 多几项：目标仓位区间（例如 BTC 50%–65%）、方向（加仓/持有/减仓/不碰）、以及“失效条件”（现在的输出里已经有 `invalidation_conditions`）。
2. **硬规则（代码，永远在最上层）**：kill switch、回撤熔断、单币上限、不用杠杆。任何模型都改不了。
3. **快思考（每天一次，不是每秒）**：只做两件事：
   - 检查失效条件有没有触发（价格暴跌、交易所出事、监管新闻），触发了就**提前叫醒 Opus 重新评估**，并暂停开新仓；
   - 在边界内挑执行时机：价差太大、波动太剧烈就推迟挂单。
4. **开仓前判断门（照搬 QuantDinger）**：每笔买单发出前过一次快模型，拒绝就不买；**卖出和止损永远不经过 AI**，模型挂了也不会把仓位锁死。

### 8.3 快层用什么模型

- 推荐 **Claude Haiku 5.5**（输入 $0.10、输出 $0.50 / 百万 token）。每天每个币一次检查约 2k token，一年 4 个币也就几毛钱，和 Opus 共用你的 $100 API 额度，不用多一个供应商。
- 也可以用 Jev，但它是 TypeSafe 单独收费的 API，不在你的 Claude 额度里。快层接口我会写成可替换的，以后想换 Jev 只改配置。
- 第一版快层先用纯代码规则（零成本），跑稳了再接模型。

### 8.4 为什么不做秒级 / 合约

- **手续费**：上面那个项目自己的数据就说明，频繁交易的亏损主要来自手续费，不是判断错。€2000 本金下这个比例更糟。
- **税**：现货持有满 1 年卖出在德国免税；秒级交易和永续合约都拿不到这个好处。
- **风险**：永续合约带杠杆，可能爆仓，和“不用保证金”的规则冲突。
- **预算**：Opus 每几分钟调用一次，一个月就会花光 $100。

## 8.5 从 X 帖子里借鉴的做法（2026-11-05）

来源：@x\_insider4 的两篇（Grok 交易台 + 第七个席位 Jev 裁判）、一篇中文的 Grok Bot 24 小时交易团队搭建教程、一篇 Grok Bot 模板合集（Minglu 提供的截图）。

| 借鉴什么 | 帖子里的做法 | 我们怎么用 |
| --- | --- | --- |
| 只给事实的档案 | HEAD 给裁判一份只有事实的档案；缺的字段写 missing，绝不猜 | 数据员给 Opus 和快哨兵的输入全部是固定字段，缺失就标“缺失”，不用上次的数字顶替 |
| 固定的封闭问题 | 每条线索都问同样措辞的 4 个问题，选项写成可核对的事实，不写“动量强”这种词 | 快哨兵只答固定问题：是否有突发事件、流动性是否正常、是否追在暴涨之后、本单要不要继续。每项都带概率 |
| 模型回答，代码决定 | 门槛写死在代码里；信心只决定买不买，不决定买多少 | 和我们现在的原则一致。门槛放在 settings.yaml，只有你能改 |
| 没回答就是不买 | Jev 没回答 = pass；不许重问同一个问题直到拿到想要的答案；“观望”只能再问一次 | 开仓门失败即拒绝；卖出和止损不经过模型。“观望”下次运行再问一次，第二次还是观望就放弃 |
| 每周校准检查 | 按概率分桶（0.70–0.79 / 0.80–0.89 / 0.90+），看各桶实际赢率；被拒的单 24 小时后会不会赚 | `ibkr-agent report` 加一张校准表：Opus 的低/中/高信心和快哨兵的概率桶，各自的实际结果。不准就提高门槛或删掉不中用的问题 |
| 席位章程 | 每个席位写清楚：负责什么、做好是什么样、在哪里停手；全台一份“交易台规矩” | 每个模型席位的提示词按这三段写；settings.yaml 就是交易台规矩 |
| 交易大厅消息流 | 每个席位在群里发消息，裁判贴出每个概率和“通过/被某项否决” | 加进理性交易台可视化页 |
| 日报/周报模板 | 发现几个、风控杀了几个、裁判 buy/watch/pass、“被裁判拒但风控是干净的”、资金变化、一件有用的事和一件要改的事 | 每周报告用这个格式，可以推送到你手机 |
| 人工签字 | 下单席位挂好单后等“APPROVE #id” | 实盘前几周可以开这个模式：计划订单发给你，你确认才下 |

**不借鉴的：** 模因币、Solana 新盘、每笔 8% 仓位、高频进出、让 Grok 直接执行。“$280 一夜变 $3,412”和“$500 五天变 $11,101”是无法核实的单次战绩，作者自己也写了“抄形状，别抄数字”和“先纸上跑门槛”。

## 8.6 价格会变：评审定计划，下单前再定价（2026-11-05）

评审链不输出“现在以 X 价买”，只输出一份**带边界的计划**：标的、方向、最多多少钱、计划价、价格带（例如 ±0.5%）、过期时间（例如 15 分钟）。

1. 交易员在发单前一秒重新取盘口；报价超过 2 秒就重取。
2. 最新价在价格带内 → 挂 post-only 限价单，限价永远不超过价格带上沿；价格跑了就不追。
3. 价格带外或计划过期 → 不下单，等下一轮。波动特别大（例如 15 分钟内 >3%）→ 快哨兵拦下并叫醒研究员。
4. 只有这一步要快，而且是纯代码（毫秒级）。Opus 的结论是“本周该不该持有、持有多少”，对 1 年以上的持有来说，10 秒内 0.3% 的波动不改变这个结论。

可视化页里小人走动是故意放慢的演示；真实运行中，除 Opus（几十秒）和 Haiku（约 1 秒）外都是毫秒级代码。
